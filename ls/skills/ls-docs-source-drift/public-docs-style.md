# Public Docs Style Guide

Public docs should be concise, source-backed, and GitHub-renderable.

## Rules

- Use relative links and relative image paths for repo-local files.
- Give every image meaningful alt text.
- Use fenced code blocks with language tags.
- Keep alerts rare and short.
- Prefer generated facts blocks for volatile version, skill, workflow, and platform counts.
- Avoid source-of-truth language for human summaries when a manifest is authoritative.
- Keep claims tied to source files listed in the truth map.

## Current external standard sources

Use current official GitHub Docs for README structure, Markdown syntax, Mermaid, Actions triggers, and writing style when the task depends on GitHub rendering or CI behavior.
