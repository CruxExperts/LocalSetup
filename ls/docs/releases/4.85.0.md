# LocalSetup 4.85.0

LocalSetup 4.85.0 adds shared GitHub CI checks and on-demand native-agent maintenance. This source candidate does not establish published release artifacts or completed fleet adoption.

## Highlights

- **Prepare repository adoption:** setup binds immutable repository IDs, full workflow pins and native validation commands to reviewed plans; fleet planning reports every discovered public repository and applies reviewed child plans individually.
- **Inspect drift and prepare bounded work:** verify reports unavailable evidence and run emits packets for the current native agent. Failed validation, dirty tracked inputs and partial push-only checks cannot establish readiness.
- **Check supported locked dependencies:** a pinned reusable workflow scans immutable Git blobs for uv, Cargo and Bun locks without executing candidate code. API-only reporting is isolated from candidate validation.

After publication, see the [release and downloads](https://github.com/CruxExperts/localsetup/releases/tag/v4.85.0) for release assets.

## Compatibility

Existing github-repo typed settings, native tests, CodeQL and release owners remain authoritative. Optional adoption is separate from maintenance-pack installation.

Task packets are preparation, not executed repairs or merge authorization. Unsupported native dispatch, signing and merge paths remain blocked.

Supported lockfile results are scoped evidence. Overall dependency and external-tool coverage remain unknown where not established; unsupported lock formats fail that scoped check. No provider configuration or workstation scheduler is installed.

Copilot activation requires verified entitlement, allowance, payer and inherited controls. This candidate does not enable paid overage, unlicensed review or cloud coding assignments.

## Update

Install or refresh the optional github-maintenance pack using the managed installer and the recorded client scope; preserve customized agent files.

Run github-maintenance setup with an explicit configuration, review its digest, and apply child plans. Publish the shared workflow before activating consumers pinned to its immutable commit.

Use github-maintenance verify and run with a repository or --all-public --owner and --checkout-root. Keep runtime evidence and private security findings outside tracked documentation.

For installation and source refresh, read the [quickstart update instructions](../QUICKSTART.md#update). Adapter changes follow the [adapter ownership guide](../ADAPTER_OWNERSHIP.md).
