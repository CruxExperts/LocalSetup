# LocalSetup 4.94.1

LocalSetup 4.94.1 integrates reviewed dependency updates, compact workload names, safer abandoned-terminal collection, and the terminal recovery and diagnostic maintenance since v4.89.10.

## Highlights

- Show compact application and command context through a shared resolver, formatter and native readback check. Keep declared dispatch, observed ancestry, caller assertions and verified LocalSetup package versions distinct; mark abbreviated or omitted command layers.
- Name explicitly requested Docker or Podman containers from the complete engine inventory, including stopped containers, and verify by native container ID. Preserve orchestrator-owned names and report inner-process naming separately.
- Collect eligible abandoned native terminal sessions without adopting or replaying commands. Preserve live workloads, admitted members, attached viewers and uncertain native state; report partial collection as a nonzero result.
- Include controller-owned remote diagnostics, private diagnostic staging, managed-generation absence fencing, user file-organization guidance, and centralized configuration-backup guidance.
- Complete the reviewed Python dependency update, synchronize the packaged SDK runtime lock and integrity receipt, and regenerate both S3 skill exports. Preserve immutable workflow action pins and the reviewed SDK helper-permission correction.

After publication, see the [release and downloads](https://github.com/CruxExperts/localsetup/releases/tag/v4.94.1) for release assets.

## Compatibility

Process and container IDs remain authoritative. Display names do not grant ownership, authentication or permission to stop work; there is no new identity registry or persistent reservation.

Native process naming is implemented on Linux. Arbitrary programs and inner container processes must cooperate after exec; other native surfaces report unsupported or unavailable. Root CLI metadata is declared; unsupported deeper dispatch is not inferred from raw arguments.

Caller-verified version flags remain assertions, not independent proof. Unverified versions are omitted and mutable image tags do not establish verified versions. Arguments, exit status and signals retain their existing semantics.

Existing containers are not renamed or recreated. Compose and scaling retain their naming authority. Native process suffix allocation is best effort, not atomic.

Automatic fresh-session handoff and semantic-memory integration remain provisional and are excluded. This release does not change provider permissions, client models, trust, schedules or host services.

## Update

Use the existing installation or source-refresh procedure within its approved scope. Publication does not deploy or refresh installed consumers automatically; retain the last qualified pin until release acceptance completes.

Inspect partial garbage-collection results rather than replaying uncertain mutations or manually targeting resources by display name.
