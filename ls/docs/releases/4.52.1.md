# LocalSetup 4.52.1

LocalSetup 4.52.1 adds an optional GitHub maintenance profile, standalone skill capture, and a shared Herdr operations suite. It also preserves deferred patrol evidence across runs and updates two Python dependencies with aligned hash-locked SDK exports.

## Highlights

- **Adopt maintenance through existing owners:** the optional github-maintenance pack provides a reusable recipe and adaptable policy, review, dependency-check, and bug-report assets. Adoption preserves existing commands, labels, review contracts, and custom files instead of silently installing a second automation path.
- **Capture completed setups as reusable skills:** the opt-in completion handoff packages the full compressed source and standalone helpers, with existing ownership and contribution boundaries. Public HTTPS origin guidance supplies the companion service workflow.
- **Operate Herdr through one shared core:** a master skill routes pane layout, command lifecycle, SSH lifecycle and tunnels, configuration, and provenance maintenance to reviewed adapters. Owned resources use explicit identities, durable completion evidence, and reconciliation after uncertain mutations.
- **Preserve patrol observations and recovery state:** manifest identities include content hashes, partially changed deferred batches retain current evidence, and obsolete markdown observations leave the queue. Unavailable history remains blocked across runs until explicit deterministic recovery, retaining known attempted and completed receipts.
- **Keep Python dependency exports aligned:** update boto3 to 1.43.114 and genai-prices to 0.1.13, preserving the transitive versions and regenerating the managed SDK and S3 skill hash-locked requirements.

After publication, see the [release and downloads](https://github.com/CruxExperts/localsetup/releases/tag/v4.52.1) for release assets.

## Compatibility

The maintenance pack is opt-in and is not added to the normal selection profile. Installing it alone does not rewrite target .github files, publish a pull request, configure CodeQL, enable Copilot, or mutate repository and account settings.

Direct patrol invocations must supply valid packet dispositions or explicitly initialize them in deterministic mode. Missing or corrupt history fails closed; uncertain provider attempts are not automatically replayed. The response schema is retained, but patrol output is factual and artifact-only.

A provider alias, a concrete model name, or a token cap does not prove low cost or remaining allowance. Concrete economical backing, protected runtime qualification, and authorized usage must be verified before model-assisted cloud activation. External upstream source freshness is not established merely by local hash changes.

The Herdr skills join the normal ops pack and use the reviewed Herdr v0.9.5 source and API baseline. LocalSetup installation does not install or upgrade a native Herdr binary by itself. Protected panes, remote authentication, shared-session interruption, and target ownership remain governed by the active repository and session authority.

Standalone skill capture remains opt-in. Capturing source does not authorize service deployment, global policy changes, contribution, or publication.

The unpublished logical slices advance in ancestry order: GitHub maintenance to 4.50.0, standalone capture to 4.51.0, Herdr operations to 4.52.0, and dependency maintenance to 4.52.1. Patrol fixups stay with their maintenance slice; generated receipts and documentation preparation add no increment. Published tags and assets remain unchanged.

## Verify the download

Focused checks cover patrol packet identity, deferred evidence, consecutive unavailable-history runs, explicit recovery, SDK dependency receipts, S3 exports, and dependency selection. Herdr source acceptance includes isolated pane ownership and real command-exit receipts. No live provider call or remote service deployment is established by these fixtures.

Before integration, require successful hosted validation of the exact signed final candidate. Separately verify CodeQL analysis, native Copilot entitlement and effective settings, actual default-branch bug intake, and the selected economical patrol model and runtime. Local source validation does not establish remote pilot activation.

Before release publication, verify the signed tag, exact source binding, downloaded archive, .sha256 checksum, .cdx.json SBOM sidecars, and cryptographic provenance. Exercise an isolated installation from the actual downloaded artifact before publishing the verified draft.
