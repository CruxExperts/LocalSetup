# LocalSetup 4.55.1

LocalSetup 4.55.1 improves managed sudo authentication, names skills and workflows for the requests that trigger them, and verifies normal personal presets from installed wheels.

## Highlights

- **Keep compatibility evidence accurate:** standalone compatibility records now identify the release that shipped each integration while retaining the original standalone candidate evidence.
- **Update security-sensitive dependencies:** runtime certificate data uses certifi 2026.10.19, and development image tooling uses Pillow 13.0.0.
- **Report sudo readiness safely:** the managed workflow distinguishes cached readiness, credential-variable outcomes, and required manual authentication. Results expose variable names and statuses, never credential values; readiness does not authorize a privileged command.
- **Find skills and workflows by task:** all 20 workflows use the compact ls-wf- prefix. The naming review renamed 84 of 113 skills and retained 29 names. Published selectors remain aliases, recorded refresh migrates renamed selections, and authoring guidance now starts with natural activation phrases.
- **Catch installed-wheel preset regressions:** a focused test builds and installs the wheel in isolation, runs the normal personal preset without a source-root override, checks that bootstrap references are present, and confirms private local-context files stay out of the install.

After publication, see the [release and downloads](https://github.com/CruxExperts/localsetup/releases/tag/v4.55.1) for release assets.

## Compatibility

The ordered targets from the verified live v4.53.3 baseline are 4.53.4 for the compatibility-record correction, 4.53.5 for dependency maintenance, 4.54.0 for managed sudo credentials, 4.55.0 for activation-based package naming, and 4.55.1 for installed-wheel regression coverage. This sequence follows corrected 4.x arithmetic; previously published tags and artifacts remain unchanged.

Published skill and workflow selectors remain accepted as aliases. Recorded package refresh, CLI package paths and package tokens resolve renamed selections to current locations while preserving custom adapter content.

The workflow checks cached sudo readiness first. When a password is required, it tries the exact target-host variable `<hostname.upper()>_SUDO_KEY`, then `GENERIC_SUDO_KEY`, before manual authentication. Output reports variable names and whether candidates were unavailable, empty, rejected or used; uncertain results are reconciled without replay. Readiness does not expand command authorization.

Runtime certifi changes to 2026.10.19 and development Pillow changes to 13.0.0. Re-sync the supported environment to receive the pinned versions.

Local installed-wheel and source-distribution checks do not qualify optional live services or establish that every platform has been exercised.
