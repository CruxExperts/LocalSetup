# LocalSetup 4.49.1

LocalSetup 4.49.1 updates the locked OpenAI and Pydantic runtime dependencies and keeps the packaged SDK dependency export and integrity receipt synchronized. The existing CLI, adapter, OpenPGP, and file-reader interfaces remain unchanged.

## Highlights

- **Update the selected Python runtime dependencies:** the locked resolution moves OpenAI from 3.28.0 to 3.29.0, Pydantic from 2.14.0 to 2.14.1, and pydantic-core from 2.50.0 to 2.50.1. No other dependency versions change.
- **Keep packaged dependencies consistent:** the SDK runtime lock and dependency integrity receipt are regenerated from the accepted resolution. The build lock and declared dependency ranges remain unchanged.
- **Make dependency refresh requirements explicit:** the SDK ownership guide identifies the receipt as part of a complete dependency update and distinguishes historical adoption evidence from the dated checks for these exact versions.

After publication, see the [release and downloads](https://github.com/CruxExperts/localsetup/releases/tag/v4.49.1) for release assets.

## Compatibility

This maintenance slice changes the repository's locked dependency resolution, not public framework APIs or the vendored SDK source. Existing wheel dependency ranges are preserved; unconstrained wheel installers may select other compatible versions.

Exact-version OSV, GitHub Advisory Database, and PyPI checks on 2026-10-17 returned no reported vulnerabilities for the three selected targets. These dated checks are not a blanket safety guarantee or a claim that every supported platform was exercised.

The corrected 4.x sequential policy counts this accepted dependency maintenance slice once as a PATCH increment from 4.49.0. Historical releases and their assets remain unchanged.

## Update

For an explicit source directory or extracted release archive, use `--sync-env` to provision its locked Python runtime. Follow the [multi-platform install guide](https://github.com/CruxExperts/LocalSetup/blob/v4.49.1/ls/docs/MULTI_PLATFORM_INSTALL.md) and preserve custom adapter content.

When maintaining dependency locks, regenerate and check the SDK exports and receipt using the [SDK ownership guide](https://github.com/CruxExperts/LocalSetup/blob/v4.49.1/ls/docs/SDK_FORK.md#managed-dependency-lock-exports). A lockfile-only update does not refresh the packaged runtime.

For installation and source refresh, read the [quickstart update instructions](../QUICKSTART.md#update). Adapter changes follow the [adapter ownership guide](../ADAPTER_OWNERSHIP.md).

Before publication, require successful exact-candidate hosted validation, including all Python shards, automated smoke checks, generated-document checks, and deterministic review. Focused dependency, provider-client, completion, and build checks supplement that full-candidate evidence.

Exercise the updated owning provider client over a local HTTP endpoint, verify its final-send identity and explicit synthetic credential, and validate the parsed response through Pydantic. This is local compatibility evidence, not live-provider qualification.

Verify the signed tag, downloaded archive, checksum and SBOM sidecars, exact source binding, and cryptographic provenance. Qualify the downloaded artifact in an isolated installation before publishing the verified draft.
