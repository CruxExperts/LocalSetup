# LocalSetup 4.89.10

LocalSetup 4.89.10 updates the pinned CI actions and Python dependencies, keeps packaged dependency exports aligned, and makes existing boundary and allocation checks more reliable.

## Highlights

- CI uses reviewed immutable pins for setup-python 7.1.0 and setup-uv 10.3.2. Regression checks enforce immutable, consistent pins without copying changing release hashes into tests; successful exact-commit validation remains reusable during main integration and publication.
- Python updates include OpenAI 3.37.0, setuptools 84.2.1, and Boto3/botocore 1.43.118, with regenerated SDK locks, integrity receipt and hashed storage requirements.
- More reliable checks: filesystem-boundary tests bind their simulated Git responses, and concurrent allocation tests separate readiness from a bounded completion watchdog. Production behavior, real locking, durable-artifact assertions and cleanup remain unchanged.

After publication, see the [release and downloads](https://github.com/CruxExperts/localsetup/releases/tag/v4.89.10) for release assets.

## Compatibility

This maintenance release preserves the framework command and file formats. Dependency exports retain their separate runtime, build and optional storage scopes.

The CI actions continue using Node 24; this update does not change the selected Python version or uv version.

## Update

Use the normal verified installation or source-refresh procedure. Source checkouts should synchronize their locked environment before running framework tools.

For installation and source refresh, read the [quickstart update instructions](../QUICKSTART.md#update). Adapter changes follow the [adapter ownership guide](../ADAPTER_OWNERSHIP.md).

## Verify the download

Focused checks passed for dependency exports and integrity, immutable action pins, client-state boundary/privacy behavior, concurrent fresh-root allocation and real holder-release behavior. A guarded one-CPU pressure trace demonstrated correct allocation finishing beyond the old five-second assertion; the fresh-root test now uses a bounded 20-second completion watchdog. Final release acceptance additionally requires successful validation of the exact candidate commit.

Verify the framework archive using its .sha256 checksum and .cdx.json SBOM sidecars.

