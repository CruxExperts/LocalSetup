# Localsetup 4.4.0

<img src="../../../assets/localsetup-logo.png" alt="Localsetup package and terminal mark" width="80">

This feature release modernizes the skill and workflow library, consolidates repeated context, and tightens the boundary between framework source, managed packages, and project-owned content.

## Changes for users

### Focused context and documented entry points

The platform templates now point to canonical skill and workflow catalogs and use the active client's discovery surface. Eight templates contain 45.5% fewer bytes than their previous versions, with task routes, safety constraints, and operational guidance preserved. This measures those optional template files; it is not a claim about every client's loaded context or token use.

The [skills and rules guide](../SKILLS_AND_RULES.md) explains which surfaces own instructions. The [platform registry](../PLATFORM_REGISTRY.md) distinguishes source templates from installed adapters.

### Workflow consolidation

The documentation-alignment, Markdown-reference audit, Codex-heartbeat, and transport-handoff workflows now live with their owning capability skills. Use the generated [workflow registry](../WORKFLOW_REGISTRY.md) and [skill catalog](../SKILLS.md) to discover the supported entry points. Avoid retaining copied inventories in client instructions.

The broader library refresh aligns command examples, validation, failure handling, and package references with their implementations. Existing operational boundaries still apply: optional automation is opt-in, custom adapter content stays in place, and a skill's presence does not authorize external actions.

### Cleaner package contents and isolated checks

Source materialization excludes `__pycache__` directories and `.pyc`/`.pyo` files. It continues to preserve Python source, hidden assets, package data, and source-symlink containment checks.

Framework audit smoke commands can use the explicitly staged shared `deps.py` helper. The sandbox validates its path and content digest and rejects undeclared helper files; it does not restore inherited host import paths.

Archived upstream source remains an immutable, selective provenance record. Active documentation links are validated separately. The [Superpowers coverage notes](../../skills/ls-superpowers-skill-mapping/references/upstream-coverage.md) explain omitted upstream auxiliary references.

## Update and verify

First refresh the registered framework source. For a managed bootstrap installation, rerun the [public bootstrap](../QUICKSTART.md#install-in-one-command) after this release is published. It resolves the latest stable release and opens the setup wizard. Review the source ref and package selection before applying. For an explicitly selected checkout, update that checkout to the intended release yourself; Localsetup does not fetch or replace it automatically.

`localsetup update` reapplies packages from the registered source; it does not download a newer framework release. Once the source is current, run from the project you intend to update:

```bash
localsetup plan --target-directory .
```

Review the resolved selection and clear any blockers before applying:

```bash
localsetup update --target-directory .
localsetup verify --level filesystem
```

Project adapters remain shared surfaces: custom skills, ordinary files, and project-owned symlinks must stay in place. See [adapter ownership](../ADAPTER_OWNERSHIP.md) and the [quickstart update instructions](../QUICKSTART.md#update).

For a fresh installation, follow the [quickstart](../QUICKSTART.md). The public bootstrap resolves the latest stable release; explicitly selected source checkouts remain source-authoritative.

## Release verification

Each published release provides a package tarball, SHA-256 sidecar, and CycloneDX SBOM. From a source checkout, verify a downloaded package with:

```bash
uv run --locked python ls/tools/localsetup.py --source-root . verify-release /path/to/localsetup-v4.4.0.tar.gz
```

The [versioning guide](../VERSIONING.md) describes the release gates and generated-document checks. Skill package versions remain separate from the framework version.
