# LocalSetup 4.53.0

LocalSetup 4.53.0 helps keep reusable guidance current with daily upstream checks and clear, evidence-backed refresh requests. It also makes the homepage easier to understand and brings guided GitHub upkeep, reusable setup handoffs, and more reliable remote work.

## Highlights

- **Know when guidance needs attention:** a daily check compares the registered Herdr sources with fresh upstream evidence. Confirmed changes become compact GitHub issues with source links and a clear handoff; unchanged findings do not create repeated requests.
- **Understand the product faster:** the refreshed homepage explains what LocalSetup does, how it helps with everyday tasks, and how to get started, using plain language.
- **Keep your GitHub project easier to maintain:** choose optional guidance for reviewing changes, reporting problems, and checking dependencies while keeping the tools and rules you already use.
- **Turn a successful setup into reusable help:** save a completed setup as a skill with its source and helper files, so it is easier to repeat or hand over.
- **Manage remote work with clearer safeguards:** the Herdr tools help organize terminal work, track completed commands, and handle remote setup, configuration, and restarts. They check ownership and active work before making changes.
- **Keep unfinished checks from getting lost:** maintenance checks retain current observations between runs. Missing history pauses actions until it is explicitly recovered, helping avoid repeated requests.
- **Refresh the Python dependencies:** update two libraries and keep their checked installation files aligned.

After publication, see the [release and downloads](https://github.com/CruxExperts/localsetup/releases/tag/v4.53.0) for release assets.

## Compatibility

The maintenance pack is opt-in and is not added to the normal selection profile. Installing it alone does not rewrite target .github files, publish a pull request, configure CodeQL, enable Copilot, or mutate repository and account settings.

Direct patrol invocations must supply valid packet dispositions or explicitly initialize them in deterministic mode. Missing or corrupt history fails closed; uncertain provider attempts are not automatically replayed. The response schema is retained, but patrol output is factual and artifact-only.

A provider alias, a concrete model name, or a token cap does not prove low cost or remaining allowance. Concrete economical backing, protected runtime qualification, and authorized usage must be verified before model-assisted cloud activation. External upstream source freshness is not established merely by local hash changes.

The Herdr skills join the normal ops pack and use the reviewed Herdr v0.9.5 source and API baseline. LocalSetup installation does not install or upgrade a native Herdr binary by itself. Protected panes, remote authentication, shared-session interruption, and target ownership remain governed by the active repository and session authority.

Standalone skill capture remains opt-in. Capturing source does not authorize service deployment, global policy changes, contribution, or publication.

The unpublished logical slices advance in ancestry order: GitHub maintenance to 4.50.0, standalone capture to 4.51.0, Herdr operations to 4.52.0, dependency maintenance to 4.52.1, the homepage refresh to 4.52.2, and daily provenance handoffs to 4.53.0. Patrol fixups stay with their maintenance slice; generated receipts and documentation preparation add no increment. Published tags and assets remain unchanged.

The homepage refresh changes presentation and navigation. Existing commands, install paths, supported tools, and package selection behavior are preserved.

The repository schedules Provenance Refresh for 6 a.m. America/Chicago each day and retains manual dispatch. Initial upstream coverage is Herdr only. Unavailable or inconclusive checks are reported as unknown, not as confirmed refresh requests. The job does not update sources, install or upgrade software, invoke models, or change QC Patrol.

Start Herdr work with `ls-herdr` and the [Herdr operations guide](https://github.com/CruxExperts/LocalSetup/blob/v4.53.0/ls/docs/ops/herdr-ops.md). Review its pinned source and the selected native endpoint before operating panes or remote sessions.

Review a provenance issue with the linked immutable upstream evidence and the existing Herdr provenance maintenance owner. An issue is a request to assess a bounded source refresh; it does not authorize host upgrades or automatic implementation.

For installation and source refresh, read the [quickstart update instructions](../QUICKSTART.md#update). Adapter changes follow the [adapter ownership guide](../ADAPTER_OWNERSHIP.md).

## Verify the download

Focused checks cover saved maintenance observations, recovery, dependency installation records, and the Herdr tools. Remote-operation tests exercise command validation, existing executable discovery, and uncertain registration recovery. Isolated native checks cover terminal ownership and actual command exit results. No live provider call or remote service deployment is established by these fixtures.

Before integration, require successful hosted validation of the exact signed final candidate. Separately verify CodeQL analysis, native Copilot entitlement and effective settings, actual default-branch bug intake, and the selected economical patrol model and runtime. Local source validation does not establish remote pilot activation.

Before release publication, verify the signed tag, exact source binding, downloaded archive, .sha256 checksum, .cdx.json SBOM sidecars, and cryptographic provenance. Exercise an isolated installation from the actual downloaded artifact before publishing the verified draft.

Download the framework archive with both its `.sha256` checksum and `.cdx.json` SBOM sidecars. Keep all three files in the same directory before running `verify-release`.

```bash
uv run --locked python ls/tools/localsetup.py --source-root . verify-release /path/to/localsetup-v4.53.0.tar.gz
```
