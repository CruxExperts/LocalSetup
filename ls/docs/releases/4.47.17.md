# LocalSetup 4.47.17

LocalSetup 4.47.17 fixes package-lock error reporting, extends journaled rollback recovery to repository-only installations, and makes package-content comparisons unambiguous while preserving legacy receipt fields. This release also refreshes reviewed Python dependencies, storage exports, and pinned GitHub Actions.

## Highlights

- **Preserve operation errors:** package-lock contention handling no longer masks filesystem failures raised inside the protected operation or during lock metadata writes.
- **Recover ordinary repository rollback:** the existing transaction now covers repository-only removal, preserves unmanaged library entries and adapter neighbors, and retains recovery evidence if restoration fails.
- **Distinguish different package trees:** framed content digests separate file paths and contents; additive provenance evidence retains historical digest fields for older readers.
- **Refresh reviewed dependencies:** synchronize the project lock, packaged SDK runtime export and receipt, and both optional storage SDK exports.
- **Keep workflow pins aligned:** update setup-uv and upload-artifact full-commit pins together with the exact-pin regression check; the selected uv runtime stays unchanged.

After publication, see the [release and downloads](https://github.com/CruxExperts/localsetup/releases/tag/v4.47.17) for release assets.

## Compatibility

Existing marker package_digest/artifact_sha256 and top-level registry digest values retain their historical calculation and path ordering. New source-backed materialization adds package_digest_framed evidence using sha256-framed-files-v1 in existing provenance snapshots; older readers can continue using the legacy fields.

Legacy-only provenance is reported as legacy-limited. Unknown or malformed framed records produce unsupported diagnostics without a silent fallback. Reports do not rewrite baselines; source-backed install/update/repair can add framed evidence. Renaming legacy content during migration does not establish that baseline.

Rollback recovery handles in-process failures and journals managed state without replacing shared adapter parents. It does not guarantee crash recovery or successful restoration when storage refuses writes. Recovery failures retain journal/backup evidence for reconciliation before retry.

The reviewed lock changes are boto3 1.43.111, botocore 1.43.112, genai-prices 0.1.10, griffelib 2.3.2, openai 3.28.0, opentelemetry-api 1.45.1, pydantic 2.14.0, and pydantic-core 2.50.0.

GitHub Actions use setup-uv 10.3.0 and upload-artifact 7.0.2 at reviewed full commit hashes. The workflow-selected uv runtime remains 0.11.21. No new provider or host sandbox qualification is claimed.

## Update

For an explicit source directory or extracted release archive, use `--sync-env` to provision the locked Python runtime. Follow the [multi-platform install guide](https://github.com/CruxExperts/LocalSetup/blob/v4.47.17/ls/docs/MULTI_PLATFORM_INSTALL.md) for adapter selection and bootstrap behavior; preserve custom adapter content and review recovery diagnostics before retrying a failed mutation.

Optional storage consumers should use each skill's regenerated requirements-s3-sdk.txt in a caller-owned environment; the tools do not install dependencies automatically. See [optional storage skills](https://github.com/CruxExperts/LocalSetup/blob/v4.47.17/ls/docs/STORAGE_SKILLS.md).

Use the [versioning guide](https://github.com/CruxExperts/LocalSetup/blob/v4.47.17/ls/docs/VERSIONING.md) for corrected 4.x release policy and historical tag treatment.

For installation and source refresh, read the [quickstart update instructions](../QUICKSTART.md#update). Adapter changes follow the [adapter ownership guide](../ADAPTER_OWNERSHIP.md).

## Verify the download

Before publication, require the complete Python test suite, documented automated smoke suite, required GitHub checks for the exact candidate, and the signed release tag. Verify downloaded archive bytes, .sha256 and .cdx.json sidecars, source/tag binding and cryptographic provenance; focused checks alone do not establish final release readiness.

Download the framework archive with both its `.sha256` checksum and `.cdx.json` SBOM sidecars. Keep all three files in the same directory before running `verify-release`.

```bash
uv run --locked python ls/tools/localsetup.py --source-root . verify-release /path/to/localsetup-v4.47.17.tar.gz
```
