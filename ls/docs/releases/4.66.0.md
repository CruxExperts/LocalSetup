# LocalSetup 4.66.0

LocalSetup 4.66.0 adds practical guidance for preparing automations, reviewing operational knowledge, contributing changes, continuing work in another workspace, and preparing private media.

## Highlights

- **Check before scheduling:** the cron readiness command reports observable prerequisites, blockers, unchecked requirements, and next actions without running or enabling a task.
- **Review guidance before retirement:** assess accuracy, review age, historical value, dependent instructions, and the limits of a usage search before changing or retiring a reference.
- **Understand recovery confidence:** report backup attempts, integrity checks, and successful recovery exercises separately, then prepare an isolated exercise that protects originals.
- **Resume a contribution:** follow receiving-project rules and keep work, review readiness, submission readiness, and confirmed submission visible in one private progress record.
- **Continue settled LSCli history in another workspace:** select the source with `--source-workspace` and the destination with `--workspace`; the new session retains exact history while requiring fresh authority.
- **Explain an unfamiliar tool from source:** write an operational reference tied to a reviewed revision, with source citations, coverage, failure and recovery behavior, and visible unresolved questions.
- **Manage local previews safely:** guide existing project commands through verified loopback startup, reuse, inspection, conflict handling, and stopping only the owned preview.
- **Prepare media metadata copies:** choose hidden fields to retain, remove, or update, preserve original files and legitimate attribution, and verify each output against the chosen policy.
- **Prepare private transcripts and captions:** check local processing capability, mark drafts, review words and timing, export sidecar captions, and optionally render a separate captioned video.

After publication, see the [release and downloads](https://github.com/CruxExperts/localsetup/releases/tag/v4.66.0) for release assets.

## Compatibility

Existing same-workspace LSCli branches remain compatible: omitting `--source-workspace` uses `--workspace` for both sessions. Both workspace directories must already exist. Branching copies settled LSCli checkpoint history, not working-tree files or another client's live conversation; the guided procedure checks client capability before a move.

The new preview, metadata, and transcription packages are instruction-only procedures. They use available project commands and installed tools; they do not bundle a server supervisor, media editor, speech engine, or model. Unsupported tools, formats, clients, or local processing remain explicit limitations rather than automatic remote fallbacks.

Cron readiness is a read-only report with ready, blocked, and unchecked findings. It does not activate cron, execute task commands, verify task-specific credentials or recovery, or infer success from enabled state. A zero command exit status means the report was produced; inspect the reported readiness before activation.

## Update

Refresh the selected LocalSetup packages through the supported install or recorded package-refresh workflow. The new contribution workflow is in dev and GitHub-maintenance selections; previews are in dev, and media procedures are in dev and frontend. The normal profile includes dev.

Use the existing documentation-alignment, backup, Git, Node, and Remotion owners to reach the extended procedures. Keep task records and private evidence under the receiving repository's private state owner; review and sharing do not imply publication authority.

For installation and source refresh, read the [quickstart update instructions](../QUICKSTART.md#update). Adapter changes follow the [adapter ownership guide](../ADAPTER_OWNERSHIP.md).

## Verify the download

Focused cron tests cover read-only reports, missing commands, log permissions, relative PATH handling, and path failures. Focused branch tests cover exact history, source preservation, destination identity, fresh authority, and rejected invalid workspaces. Guided packages have scenario review and catalog/package validation; this does not qualify every external tool or media format.

Before publishing an archive, require the final candidate's applicable full-suite and documentation evidence, verify its signed source and tag, and check the archive with its checksum and SBOM sidecars. This source update prepares guidance and does not itself publish a release.

Download the framework archive with both its `.sha256` checksum and `.cdx.json` SBOM sidecars. Keep all three files in the same directory before running `verify-release`.

```bash
uv run --locked python ls/tools/localsetup.py --source-root . verify-release /path/to/localsetup-v4.66.0.tar.gz
```
